Maurice Sapp Artifact: CS-340-Client-Server-Development-2026 Artifact Description The artifact I chose is my CS-340 AnimalShelter project. It is a Python program that connects to a MongoDB database and allows users to perform CRUD operations, which includes creating, reading, updating, and deleting records. The program was originally developed during my coursework to demonstrate how a Python application can communicate with a database and manage stored data. My project works as a simple backend system where data is stored in MongoDB and then retrieved or modified through Python functions. Looking back at it, it helped me understand how real applications are structured behind the scenes, especially how data is not just stored, but constantly accessed, updated, and managed depending on user input. It also gave me a better understanding of how client-server style systems work in practice. My Reason for Choosing the Artifact and the Improvements I Made I chose this artifact because it connects closely to my career goal in Health IT Support. In healthcare systems, especially things like electronic health records, data needs to be stored correctly, updated often, and retrieved quickly when needed. This project reflects those same ideas, even if it’s on a smaller scale. It shows that I understand how database systems work and how applications interact with stored data. When I went back to improve the project, my main focus was making the code cleaner, more organized, and more reliable. The original version worked, but a lot of the logic was grouped together in a way that made it harder to read and maintain. To fix that, I broke the code into smaller, more focused methods. For example, I separated out the database connection logic so it is handled in one clear place instead of being mixed into other parts of the program. I also added a validation method that checks the data before it is inserted or updated in MongoDB. This step is important because it prevents empty or incorrect data from being stored in the database. Before this change, the program would accept whatever was passed in without really checking it, which could lead to issues later on. An additional improvement I made was strengthening error handling. In the original version, errors were mostly handled with basic print statements, which didn’t give much detail. In the updated version, the program now gives clearer and more meaningful feedback when something goes wrong, especially when there are database connection issues or failed operations. This makes it easier to understand what is happening instead of just seeing a generic error. I was also able to expanded the functionality of the project by completing the full CRUD system. Originally, my program only supported create and read operations. So, I added update and delete methods so the system is fully functional as a complete database application. This makes it closer to something you would actually see in a real-world system instead of just a simple example.
